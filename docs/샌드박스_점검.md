# 샌드박스 점검

## 왜 하나

[새 노트북 세팅](새_노트북_세팅.md)의 자동 점검 가능한 경로를 깨끗한 윈도우에서 증명합니다.
호스트에서 명령 하나를 실행하면 10단계의 PASS/FAIL 표가 나옵니다.
로그인과 실제 글 생성은 아래 수동 점검표로 확인합니다.

## 언제 하나

- 모임 전날
- 세팅 문서나 frame을 바꾼 PR을 머지한 뒤
- 한 달에 한 번

## 준비

Windows 11 Pro/Enterprise가 필요합니다. BIOS에서 가상화를 켭니다.
메모리는 8GB 이상 여유를 권장합니다. 인터넷 연결도 필요합니다.
Windows Sandbox가 없다면 관리자 PowerShell에서 실행하고 재부팅합니다.
점검 스크립트는 기능을 자동으로 켜지 않습니다.

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All
```

## 흐름

```text
호스트 명령 → wsb 생성 → 샌드박스 부팅 → guest 10단계
→ results.json/done.json → 호스트 표 출력 → 창 닫기
```

## 실행

호스트 PowerShell에서 `abbys-ai-setup` 폴더로 이동해 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\sandbox\Start-SandboxCheck.ps1
```

기본값은 GitHub의 `ulsan-abbys` 아래 두 저장소의 `main` 브랜치입니다.
Git이 있으면 clone하고, 없으면 ZIP을 받습니다.
다른 브랜치는 `-Branch 브랜치명`으로 지정합니다. 두 저장소에 같은 브랜치가 있어야 합니다.

아직 푸시하지 않은 변경은 로컬 모드로 확인합니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\sandbox\Start-SandboxCheck.ps1 -Source local
```

기본 `LocalRoot`는 이 저장소의 부모 폴더입니다.
다른 위치라면 `-LocalRoot "E:\작업 폴더"`를 추가합니다.
그 폴더에 `abbys-ai-setup`과 `abbys-content-frame`이 모두 있어야 합니다.
호스트 원본은 읽기 전용입니다. 샌드박스 내부 복사본에서 실행합니다.
`.git`, `.venv`, `logs`, `__pycache__`, `.pytest_cache` 폴더는 복사하지 않습니다.
로컬 모드에서는 `-Branch`를 사용하지 않습니다.

결과는 기본적으로 `%TEMP%\abbys-sbx\yyyyMMdd-HHmmss`에 남습니다.
`-OutDir "C:\sandbox-check\run1"`로 바꿀 수 있습니다. 새 폴더나 빈 폴더를 지정하세요.
`-TimeoutMin 25`가 기본 대기 시간입니다. 매분 경과 시간을 표시합니다.
`-NoLaunch`는 파일만 만듭니다. Sandbox 실행 가능 여부와 기존 실행 여부는 여전히 확인합니다.
`-MemoryMB 2048`은 샌드박스 메모리를 정합니다(저사양 노트북 흉내). `-NoNetwork`는 네트워크를 끕니다 — 점검기가 고장을 실패로 잡는지 보는 음성 대조용이며, 결과는 반드시 1이어야 합니다. `-Label`은 실험 이름입니다. 조건과 호스트 남은 메모리는 결과 폴더의 `config.json`에 함께 남습니다.
이 모드의 종료코드 0은 파일 생성 성공이며 10단계 통과를 뜻하지 않습니다.

## 결과 읽기

| 호스트 종료코드 | 의미 |
|---|---|
| 0 | 필수 9단계 통과, 전체 10단계 기록 완료 |
| 1 | 필수 단계 실패, 실행 중단 또는 결과 파일 오류 |
| 2 | Sandbox 미설치, 이미 실행 중, 입력·준비·실행 오류 |
| 3 | 제한 시간 초과 |

표에는 단계, 결과, 종료코드, 기대 종료코드, 걸린 초가 나옵니다.
`frame check`의 종료코드 1도 해당 단계의 기대값이면 PASS입니다.
환경 단계는 정보용입니다. 나머지는 모두 필수입니다.

`results.json`은 매 단계 뒤에 저장합니다. `contains_ok`는 필수 문구 확인 결과입니다.
`done.json`은 실행 종료를 알립니다. `passed`와 `failed`는 필수 단계 기준입니다.
전체 실행이 중단되면 `failed`에 중단 오류도 반영합니다.
`done.json`이 있어도 PASS를 뜻하지 않습니다.
`o_*.txt`에 단계별 명령 출력이 있습니다. `transcript.txt`는 진행 기록입니다.
전체 실행 오류가 있으면 `fatal.txt`도 확인합니다.
시간 초과 시에도 같은 폴더에서 부분 결과를 확인합니다.

## 샌드박스로 확인 못 하는 것 + 실제 노트북 수동 점검표

Sandbox PASS는 아래 항목을 보장하지 않습니다. 실제 사용할 노트북에서 확인하세요.

- [ ] Claude 브라우저 로그인 완료
- [ ] `claude`로 `examples\clinic`에 초안 1편 생성
- [ ] `winget install --id Git.Git -e`로 Git 설치 후 새 창에서 버전 확인
- [ ] 회사 보안 정책과 프록시 환경에서 설치·접속 가능
- [ ] 현장 와이파이 연결과 다운로드 가능
- [ ] 발표 화면 연결과 해상도 확인

## 문제 해결

- PowerShell 5.1의 Transcript는 exe 출력을 놓칩니다. 각 명령은 `cmd /c`로 파일에 출력을 모읍니다. `o_*.txt`를 먼저 보세요.
- Claude 설치 스크립트는 `ErrorActionPreference`를 `Stop`으로 바꿉니다. guest는 설치 직후 `Continue`로 되돌립니다.
- 한글 경로는 따옴표로 감싸세요. 직접 입력할 때는 Tab으로 완성하세요.
- 샌드박스는 한 번에 하나만 실행합니다. 기존 창을 닫고 다시 실행하세요.
- 창을 닫으면 샌드박스 내부 내용은 사라집니다. 호스트의 결과 폴더는 남습니다.
- 시간 초과는 샌드박스를 자동으로 종료하지 않습니다. 로그를 확인한 뒤 창을 닫으세요.
- 같은 OutDir로 재실행하면 이전 증거와 섞이지 않도록 거부합니다. 새 OutDir를 지정하세요.
- uv 단계가 `The remote name could not be resolved`로 끝나면 인터넷이 아직 연결되지 않은 것입니다. 샌드박스는 로그인 직후 몇 초간 주소를 못 찾을 수 있어 1단계가 기다립니다. 실제 노트북에서도 와이파이 연결을 확인하고 다시 실행하세요.
- 샌드박스 창이 도중에 꺼지면 호스트는 알아채지 못하고 시간 초과까지 기다립니다. 창이 없는데 경과 시간만 늘면 Ctrl+C로 멈추고 새 OutDir로 다시 실행하세요.
- Claude Code 설치가 `Checksum verification failed`로 끝나면 내려받기가 중간에 끊긴 것입니다(약 340MB). 호스트 메모리가 부족할 때 잘 생깁니다. 다른 프로그램을 닫고 다시 실행하세요.

생성·구문 검증과 실제 샌드박스 10단계 통과는 별개입니다. 실제 실행 증거는 각 실행의 결과 폴더에 남깁니다.
