# 서브에이전트 잘 쓰기

서브에이전트는 일을 나눠 맡는 보조 AI입니다. 작은 일은 직접 시키고, 나눌 이유가 있을 때만 씁니다.

| 원칙 | 적용 |
|---|---|
| (1) 결과만 필요할 때 맡긴다 | 조사 과정 전체 대신 요약과 출처를 받습니다. |
| (2) 독립된 일은 동시에 | 서로 결과를 기다리지 않아도 되는 일을 나눕니다. |
| (3) 일에 맞는 크기의 모델 | 단순 요약에는 작은 모델, 어려운 판단에는 알맞은 모델을 고릅니다. |
| (4) 지시서는 구체적으로 | 범위와 결과 형식, 끝 기준을 적습니다. |
| (5) 한 건은 직접 원문과 대조 | 표의 한 행이라도 출처를 열어 확인합니다. |
| (6) 판단은 내가 | 채택·수정·게시 여부는 사람이 정합니다. |

## 7줄 지시서

```text
목표: ○○를 조사한다.
범위(어디서): ○○ 자료만 읽는다.
산출물 형식: ○○ 열을 가진 표로 쓴다.
끝 기준: ○○건과 출처를 정리한다.
하지 말 것: 추측, 파일 삭제, 자동 게시.
번호 붙여 저장: 결과를 01_주제.md처럼 저장한다.
확인은 별도 세션에서: 원문과 결과 한 건을 대조한다.
```

## 예시: 블로그 자료 조사 3건

직접 고른 자료 3개를 프로젝트의 `자료` 폴더에 넣고 아래처럼 요청하세요. 이 예시는 3개로 나누는 연습입니다. 늘 3개를 쓸 필요는 없습니다. 현재 도구에서 서브에이전트를 사용할 수 있는지 먼저 확인하세요.

```text
블로그 자료 조사 3건을 서브에이전트 3개로 나눠 맡기고 결과를 표로 받아 줘.
목표: 울산 생활 정보 블로그의 글감 후보를 찾는다.
범위(어디서): 자료/01.md, 자료/02.md, 자료/03.md를 각각 한 명에게 맡긴다.
산출물 형식: 자료 번호 / 핵심 사실 / 원문 위치 / 글감 / 남은 질문 표.
끝 기준: 각 자료에서 사실 2개와 글감 1개를 정리한다.
하지 말 것: 자료 밖 추측, 다른 담당자의 파일 수정, 자동 게시.
번호 붙여 저장: 결과/01_조사.md, 결과/02_조사.md, 결과/03_조사.md.
확인은 별도 세션에서: 내가 표 한 행을 골라 원문과 대조한다.
마지막에는 세 결과를 한 표로 묶고, 채택 판단은 내게 남겨 줘.
```

별도 세션에서는 “결과/01_조사.md의 첫 사실을 자료/01.md와 대조하고, 일치 여부와 원문 위치만 알려 줘”라고 요청합니다. 사람도 해당 원문을 열어 확인합니다.
