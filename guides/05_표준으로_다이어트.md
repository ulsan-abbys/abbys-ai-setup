# 05. 튜닝의 끝은 순정 — 붙였다가, 표준으로 다이어트

> 운영자가 실제로 쓰는 방법입니다. 하네스·스킬·루프·그래프를 공부하고 붙여 보다가
> 결국 **프론티어 모델 회사가 권장하는 구성이 더 유리하다**는 결론에 닿았습니다.

## 왜 표준이 기준선인가

- 모델을 가장 잘 아는 건 만든 회사입니다. Anthropic·OpenAI는 규칙 파일 크기와 컨텍스트를 어떻게 작게 유지할지 공식 가이드를 냅니다.
- 모델이 좋아질수록 예전 기법은 모델 안으로 들어갑니다("단계별로 생각해" 등). 직접 만든 구조가 오히려 짐이 되기도 합니다.
- 깊이 투자할 시간이 없다면, 구조는 표준에 맡기고 내 시간은 **지식 정리**(내 일·내 결정·내 자료)에 쓰는 편이 남습니다.

## 순환 4단계

| 단계 | 하는 일 |
|---|---|
| (1) 모으기 | 새 기법·강의·사례를 모은다 |
| (2) 붙여 보기 | 내 일에 직접 구현해 본다 (작게, 한 번에 하나) |
| (3) 대조 | 공식 권장 구조와 비교한다 |
| (4) 덜어내기 | 겹치거나 표준에서 벗어난 것을 지운다 |

몇 달에 한 번, 또는 도구가 크게 바뀌었을 때 (3)~(4)를 돌립니다.

## 다이어트 점검 4문항

1. 규칙 파일이 공식 권장 길이 안인가? (CLAUDE.md 200줄 이하 · codex AGENTS.md 합산 32KiB에서 잘림 · 권장 150줄 이내)
2. 모델이 이미 하는 일을 시키고 있지 않나? ("다시 검토해", "단계별로 생각해", 과한 "반드시·CRITICAL")
3. 같은 규칙이 두 군데 적혀 있지 않나? (전역 규칙과 프로젝트 규칙, 규칙 파일과 스킬)
4. 한 달 동안 한 번도 안 쓴 스킬·규칙이 있나? → 지운다

## AI에게 맡기는 프롬프트

```
이 폴더의 AGENTS.md·CLAUDE.md·스킬 파일을 읽고, guides/05_표준으로_다이어트.md의 점검 4문항으로 진단해 줘.
지울 것·합칠 것·공식 문서와 어긋나는 것을 표로 보여 주고, 바로 지우지 말고 내 확인을 받아.
공식 문서 링크로 근거를 붙여 줘.
```
